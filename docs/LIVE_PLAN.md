## 1. 메뉴 구조 (EV211서버접속 → "라이브")

서버 IP 입력 없음(모드 A 와 구분). 3진입점:

1. **라이브 개설** (로그인 = 기기 승인 필요)
   - 개설 시: 접속코드(6자리)+QR, 송신 비번(6자리) 자동 생성
   - AI 통역: 언어별 채널 다중선택(체크박스). 목소리 선택은 Edge 경로 전용
   - 무전기 채널 개설 포함(개설자 계정 귀속)
   - 개설 직후 송신 화면으로 진입해 원어 송신 가능
2. **송신자이신가요?** (로그인 불필요)
   - QR 스캔 또는 접속코드 입력 + 송신 비번 → 통역 언어 채널 선택/생성 후 송신
   - 인간 통역사 송신 지원(AI 없이 특정 언어 채널에 직접 송신)
   - Edge PC 는 로그인(api_key) 연동이라 코드·비번 없이 송신
3. **수신(라이브 참여)** (무인증)
   - QR 카메라 스캔 또는 접속코드 입력 → 언어 채널 선택 → 수신
   - resolve 응답의 transport(sfu/chunk)로 화면 분기(기존 계획 유지)

## 2. 시스템 간 계약

```
앱 ── 접속코드 resolve ──▶ ev211.com  (라이브 메타·transport·field 서버 주소·언어 목록)
앱 ── 미디어(SFU) ───────▶ field-server (주소는 resolve 로 받은 값)
Edge ── api_key ─────────▶ ev211.com  (라이브 개설·chunk 업로드, 기존 계약 유지)
field-server ── 검증 콜백 ─▶ ev211.com  (라이브별 송신 비번·개설자 확인, SEND_CODE_DELEGATION 확장)
```

- SEND_CODE_DELEGATION.md 의 "조직 상시 송신 코드"는 **"라이브별 송신 비번"으로 대체**된다(콜백+캐시 구조는 유지, 조회 키가 코드→라이브+비번).

## 3. 개발 순서

1. **Rails(ev211.com)**: 라이브 명칭 통일 → 접속코드 신형식(대문자+숫자, 기존 통일 마이그레이션) → field 서버 주소 설정(슈퍼어드민) → resolve API 확장(transport·server_url·언어) → 기기 승인 API(연동 코드 발급/승인) → 라이브별 송신 비번 발급 → 무전기 개설 API
2. **field-server**: 라이브별 송신 비번 검증(ev211.com 콜백, FIELD_SEND_AUTH_MODE 스위치) → 무전기 개설자 귀속 → signal_events 에 라이브 ID 기록(과금 근거)
3. **앱**: 라이브 허브 3진입점 → 기기 승인 UI → QR 스캔(폰서버 코드 재사용) → 송신(원어)+언어 채널 선택 → transport 분기 수신
4. **Edge PC**: 신형식 접속코드 표시·QR, 라이브 명칭 반영
